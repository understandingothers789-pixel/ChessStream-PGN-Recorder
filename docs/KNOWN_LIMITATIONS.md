# Known limitations and validation status

This is implemented desktop software with a working capture/vision/chess/storage pipeline and measured browser-image tests. It has not undergone Windows 11 runtime acceptance testing or long-duration testing on arbitrary YouTube streams. The Windows CI workflow is ready to run; its result is not claimed.

1. **Recognition coverage is limited.** The bundled model matches five 2D piece sets. Actual captured-image validation covers Cburnett/Lichess and calibrated Neo/Chess.com. Novel sets, 3D boards, low-resolution video, heavy JPEG artifacts, altered piece proportions, strong tinting and large overlays can prevent recognition. Calibration requires the true initial position and explicit confirmation. Calibration should be repeated if the set or appearance changes substantially.
2. **Confidence is heuristic similarity.** The displayed percentage is not a measured probability of accuracy. Legality constrains errors but cannot prove a confidently misclassified legal position is the real human game. Review exports before relying on them for serious analysis.
3. **Capture requires visibility.** MSS captures the displayed pixels, including other windows over a browser. Minimized windows, DRM-protected output, virtual desktops not currently shown and a browser hidden behind this app are not captured. Use a second monitor, split-screen or position the recorder away from the board. There is no Windows Graphics Capture occlusion-independent backend in this version.
4. **Layout recovery is bounded.** Tracked application windows follow client position/size. Windows drawn regions remember their containing window and attempt full-window reacquisition on loss. Tight static regions on non-Windows hosts require adjustment if the board moves outside them. Changes in monitor DPI, HWND replacement and fullscreen transitions need Windows hardware validation. Cross-monitor region drawing is intentionally limited to one monitor per selection.
5. **Missing moves have information limits.** The search finds all legal alternatives at the shortest matching depth, up to configured time, node and ply limits. There can be other longer histories, particularly unseen reversible moves. A repeated identical position gives no evidence of unseen cycles. Different move orders that reach the same board remain ambiguous permanently unless intervening frames or manual information disambiguate them. No engine or plausible human move ranking is used as proof.
6. **Fast bullet can exceed sampling.** Adaptive six-fps recognition helps, but animation stability gates and roughly 140-ms CPU classification limit throughput. Move bursts exceeding the reconstruction budget leave a gap for later evidence or manual SAN correction. This implementation does not promise complete reconstruction at arbitrary bullet speeds.
7. **Midgame state is partly invisible.** Earlier moves are unavailable. Turn is inferred from the next shortest legal transition; castling rights and en passant are conservatively unset unless supplied through an exact initial FEN. Halfmove counters/history and threefold/fifty-move claims cannot be reconstructed from a single midgame board. An initial PGN before side-to-move inference is provisional and explicitly annotated.
8. **Live play versus review is intrinsically ambiguous.** Legal analysis moves can be indistinguishable from actual play. Known historical positions are treated as review when no short live continuation explains them; a plausible short legal review continuation can still look like live play. New standard-start games are separated after terminal results or a witnessed reset followed by a divergent legal opening. Identical opening replays wait. Unrelated midgames do not automatically replace a recording. Use Pause during known analysis, or confirm a new game.
9. **Board-only results are limited.** Checkmate, stalemate and board-provable outcomes can be set automatically. Resignation, timeout, agreed draws and player identities require editing when known. Imported PGNs retain original comments/variations, but editing their headers regenerates the recorded mainline and can omit imported variations/comments; originals should be backed up.
10. **Installation is unsigned.** The assembled NSIS executable contains official Windows runtime binaries and Windows wheels. Its PE structure and contents can be inspected on Linux, but installation, shortcuts, global hotkeys, capture permissions and multi-monitor scaling must be checked on Windows. No signed publisher certificate or completed Windows test result is claimed.
11. **Scheduled deletion needs the app running.** Overdue jobs run on next launch. The app does not install a Windows background service or wake a sleeping computer. Deletion is permanent after confirmation. External exports are outside screenshot deletion; independent game deletion removes internal PGN autosaves only.
12. **No trained ONNX weights are bundled.** The ONNX interface is functional for models following the documented contract, but requires a separately supplied compatible model and installation of the optional runtime. The self-contained installer uses the bundled template model and does not contain ONNX Runtime.

The controlled browser fixture results in `evaluation.json` are not a statistical study of chess streams, compression, piece themes or machines. Windows CPU/GPU utilization and long-running live memory use remain unmeasured.
