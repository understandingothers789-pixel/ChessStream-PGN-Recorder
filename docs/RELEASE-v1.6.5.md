# ChessStream PGN Recorder v1.6.5

- Startup now arms recording by default. Once a stable opening move is visible, recording starts automatically; the untouched initial board remains in preview. The UI switches its Start/Pause/Stop controls when automatic recording begins. Settings can disable automatic starts, and Stop also stops the armed preview.
- A weak unrelated square such as the empty d6 square in the reported e4 screenshot no longer blocks a short opening. Up to two uncertain unchanged squares can use the starting-position hypothesis; move source/destination evidence is still required.
- Initial opening reconstruction now chooses one shortest legal line with pawn moves first, instead of refusing every ambiguous order. It supports up to six plies and six displaced starting pieces under computational limits. Guessed prefixes receive PGN notes, move comments and amber **≈** markers in the live move list. The final move remains provisional under opponent-response protection.
- Resuming an application-created early FEN recording can restore its omitted opening before the recorded continuation. The same game ID, recorded moves, variations and move clocks are retained, with a diagnostic audit entry.
- Opening search stops after the first prioritized shortest path once shorter depths have been ruled out; other reconstruction callers retain exhaustive tie handling. Tighter castling target bounds avoid unnecessary opening trees.
- Screenshot image saving remains off by default. No model weights or runtime dependencies were changed.

Regression coverage includes an actual retained Chess.com e4 browser capture with the reported d6 confidence fault simulated, the five-ply `e4 c5 d3 Nc6 c3` position, pawn-first ordering, opt-out, no start on the untouched board or sparse endgames, hidden destinations, provisional hovers, GUI control transitions, completed-game separation and restoring an old early-FEN game with its clock comment. The full focused suite contains 32 tests. The supplied inline images were inspected visually; they are not byte-identical fixture files. Windows packaging, bundled inference and launcher checks run in tagged CI. Exact ordering of unobserved opening moves remains a documented guess.
