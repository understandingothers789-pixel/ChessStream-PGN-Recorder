# ChessStream PGN Recorder v1.6.11

- Hold an inactive-side-only move as a possible premove before searching for missing moves. Do not invent opponent waiting moves to make Qg7# legal. Time-based acceptance does not override this guard. The preview can show the premove while the PGN retains the played position.
- Resignation discards the premove and records the result/termination at the last played position. An independently visible preceding pending Qh6 can still be confirmed. An observed opponent move followed by Qg7# is recorded normally. Timed checkmate acceptance now updates the result immediately.
- Retry board-focused OCR when the larger image yields no result or loses the resignation subtitle. Map crop coordinates back into the original image. A pending OCR name change no longer suppresses a strong end message. Resignation-only text can mark play ended with unknown result; ordinary Resign buttons cannot.
- Retain up to 12 changed board frames in RAM, bounded to 768 pixels per side, with identical-frame timestamp refresh. Images are never written by this buffer; screenshot saving remains off by default.
- Use a separate single-worker legal-gap recovery task with bounded, progressively larger budgets up to 1.5 seconds. Retained intermediate observations can guide the reconstruction. Capture continues during recovery; stale results are discarded when the game, root, prefix or observed target changes. Premoves, rewind review and completed games cannot receive a continuation. Background guesses retain PGN annotations and diagnostic events.
- Rename the live inferred-ply summary so later inferred moves are not mislabeled opening guesses. No models or dependencies changed.

Diagnosis: the prior forward search could add a plausible unseen Black move when the screen showed only an out-of-turn White premove, then create long reversible detours to reconcile later frames. A half-second comparison interval was not itself a hard calculation timeout, but repeatedly restarting the same short search limited recovery. Full-image OCR downsampling and the player-identity gate were additional ways a resignation banner could be missed. These are verified code paths and controlled reproductions; the exact trigger in the submitted video cannot be established without its original frame/log sequence.

Validation: 53 focused local tests passed in approximately six seconds. New coverage includes the supplied-position Qh6/Qg7 premove geometry, ten-second holds, saved recovery, resignation excluding Qg7, resignation confirming a real pending Qh6, actual Black b4 followed by Qg7#, bounded/deduplicated RAM buffering, reconstruction through intermediate positions, stale asynchronous result rejection, board-crop coordinate mapping and name-change-independent result handling. The native board-crop OCR retry also passes against an existing real Chess.com resignation capture. The supplied inline image pixels were not available as fixtures; no video-specific accuracy claim is made. Tagged CI builds/tests Windows portable inference, OCR and launcher startup.

Limits: an image alone cannot prove every premove or distinguish all unseen move cycles. The guard needs a reliable prior board and turn; uncertainty remains explicit. Background work adds bounded CPU/RAM usage, and no CPU benchmark or guaranteed 2-FPS throughput is claimed. Existing already-corrupted historical PGNs may require manual correction or joining; this release does not rewrite them without new evidence.
